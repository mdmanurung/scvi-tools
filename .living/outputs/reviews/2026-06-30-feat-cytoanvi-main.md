## Key decisions in this analysis

- **Nuñez annotation source** — Ground-truth labels generated by CytoVI Leiden clustering on ALL cells (including future test cells). Labels reflect CytoVI's latent geometry, not an independent gold standard. See F1.
- **B3 primary metric is concordance not accuracy** — p2_concordance_vs_knn measures agreement between two methods, not correctness against expert labels. See F2.
- **B5 headline = best_auroc (max over 13 types)** — mean_auroc is also computed but best_auroc is the key the aggregator reads first. No FDR correction applied. See F3.
- **B4/B6 drift metric was measuring query cells, not reference cells** — fixed in local uncommitted code; not yet in branch. See F4.
- **B8 evaluation includes internal-node cells for leaf-only HCE predictions** — fixed in local uncommitted code; not yet in branch. See F5.
- **TrainRunner default accelerator changed from `'auto'` to `'gpu'`** — breaking for CPU-only environments. See F9.

## Questions for the analyst

1. **Are Nuñez test cells ever seen during label generation?** The current annotation flow runs CytoVI on all cells then Leiden-clusters them. If the answer is yes (see F1), do the Roider results (where annotation is independent of training) serve as the clean external validation, making Nuñez results supplemental rather than primary?

2. **Is B5 intended to measure uncertainty calibration (transductive) or true OOD detection (inductive)?** If novel cells are in training with labels blanked, the task measures whether the model is more uncertain about cells whose labels it never saw — which is a weaker claim than detecting truly new populations. Clarifying this changes whether F6 is a bug or a design choice.

3. **Is Phase 2 (continual update) a core claim of the paper or a described feature?** If it is a core claim, B4 needs real rLN vs FL/MCL biological splits and the EWC save/load bug (F13) must be fixed. If it is "described as available," demoting to supplement removes the need for B4/B6 being publication-grade.

4. **Which datasets use CyTOF (cofactor=5 correct) vs conventional/spectral flow (cofactor 150–2000 needed)?** The Nuñez dataset documentation is ambiguous — ARCSINH_COFACTORS['nunez'] = 2000 in preprocessing.py but the actual preprocessing call uses default cofactor=5. See F15.

5. **Should the `cytoanvi` package continue to be separated from `scvi-tools` (top-level `cytoanvi.CytoANVI`) or re-integrated under `scvi.external`?** The current CHANGELOG and some older comments still reference the old path, suggesting the separation may have happened mid-development. The ADRs clearly chose top-level package; the CHANGELOG just wasn't updated. See F21.

##### F1. Nuñez ground-truth labels derived by CytoVI trained on all cells including future test cells
`benchmarks/cytoanvi/annotate_nunez.py:185`
```python
adata = load_nunez_merged(data_dir)           # loads batch1 + batch2 together
annotate_with_cytovi_tutorial(adata, ...)      # trains CytoVI on full merged set
# writes cell_type col → data/nunez_annotated.h5ad
```
**Why it matters here**: B1/B2/B5/B8/B9 all split 20% as holdout after loading this file. The holdout cells' Leiden cluster assignments were shaped by their own presence in CytoVI training — their latent positions are jointly optimised with all other cells. The label quality of exactly the cells being tested is inflated relative to what would be seen with a held-out annotation model. Bias direction is upward for label stability at cluster boundaries, which could either inflate or deflate apparent method performance depending on whether test cells sit near boundaries.
**Fix**: Run CytoVI annotation on the 80% train cells only; transfer labels to the 20% test cells via k-NN in latent space. Or run annotation on batch1 only and transfer to batch2, achieving natural batch-level separation. Store as `nunez_annotated_v2.h5ad`.

##### F2. B3 concordance metric is circular — measures method agreement, not accuracy
`benchmarks/cytoanvi/tasks.py:255`
```python
out["p2_concordance_vs_knn"] = metrics.concordance(pred[is_p2], knn_full[is_p2])
# concordance = (pred_a == pred_b).mean()
```
**Why it matters here**: Both `pred` (CytoANVI) and `knn_full` (CytoVI k-NN) are trained on the same merged dataset with the same P1 labeled cells. P2 cells have no held-out true labels. High concordance is compatible with both methods being wrong in the same direction (shared mode collapse, shared batch artifact). Low concordance does not mean CytoANVI is wrong. Reporting p2_concordance_vs_knn as a B3 headline implies it validates CytoANVI's cross-panel accuracy — it does not.
**Fix**: Primary B3 metric should be `p1_holdout_macro_f1` (has ground truth). If P2 expert labels exist for a subset of donors, use those. Otherwise rename to `p2_inter_method_agreement` and move to supplemental diagnostics with explicit wording.

##### F3. B5 reports best_auroc (max over 13 types) as headline; no FDR correction
`benchmarks/cytoanvi/tasks.py:343` and `benchmarks/common/aggregate_results.py:86`
```python
"best_auroc": float(max(aurocs))   # max over 13 held-out T cell types
# aggregate_results.py line 86 surfaces best_auroc as first key
```
**Why it matters here**: For N=13 types with per-type AUROCs drawn from any distribution, the expected maximum under a null model is N/(N+1) ≈ 0.93 even with a random uncertainty scorer. The observed best_auroc of 0.744 (Tfh) is the max of 13 correlated draws without any correction. The defensible headline is `mean_auroc` (0.467, already computed at line 344), but it is listed second and the aggregator keys on best_auroc first. A reviewer running FDR on the per-type p-values will immediately reject the best-AUROC gate.
**Fix**: Promote `mean_auroc` as the primary B5 headline in `aggregate_results.py`. Apply Benjamini–Hochberg FDR to one-sided per-type AUROC p-values (computable as `U_stat = AUROC * n_novel * n_ref; p = norm.sf(z)`) before claiming any single type is detectable. See Idea 5 in `analysis/ideas/2026-06-30-publication-readiness/02_statistical-methods-critic.md` for exact implementation.

##### F4. B4/B6 drift metric measures query cells (expected to change), not reference cells (should not change) — FIXED locally, not yet committed
`benchmarks/cytoanvi/tasks.py:2849–2853` (diffed version)
```python
control = query_adata[:n_ctrl]   # query cells
# ...
out["control_latent_drift"] = _control_latent_drift(ref_model, updated_model, control)
```
**Why it matters here**: EWC's purpose is to prevent catastrophic forgetting of the REFERENCE representation. The reference cells should drift minimally after surgery; the query cells are EXPECTED to drift (that is the goal of surgery). Using minimum query drift to select lambda in B6 (`argmin(drifts)`) selects the lambda with least surgery effect — which is lambda=1000 (maximum regularisation) by construction. The local uncommitted code correctly uses `_replay_latent_drift` on reference/replay cells.
**Fix**: Commit the local fix immediately. The key change: use replay cells (reference cells selected by uncertainty) for drift measurement, not query cells.

##### F5. B8 evaluates HCE with leaf_only=True against true internal-node labels — FIXED locally, not yet committed
`benchmarks/cytoanvi/tasks.py:3017` (diffed version)
```python
hier_metrics = metrics.label_transfer_metrics(true[held], hier_pred[held])
# hier_pred from predict_hierarchical(leaf_only=True) — can never predict internal-node labels
```
**Why it matters here**: The default synthetic hierarchy has internal nodes (label_1 parent of label_2/label_3) that appear as observed cell labels. Any held cell whose true label is an internal node gets a systematic penalty from `hier_pred` (which can only emit leaf labels) that `flat_pred` does not get. This biases `delta_hierarchical_vs_flat_macro_f1` toward negative values regardless of HCE architecture quality. The local uncommitted code correctly filters to `leaf_held` before evaluating both methods.
**Fix**: Commit the `leaf_held` filter from the current local code before reporting any B8 results.

##### F6. A3 KNN imputation baseline uses transductive fit_transform (holdout cells in training set)
`benchmarks/cytovi/tasks_imputation.py:118`
```python
knn_imp = KNNImputer(n_neighbors=knn_neighbors).fit_transform(x)[holdout_idx, midx]
# x contains both pseudo_0 (train) and pseudo_1 (holdout) cells
```
**Why it matters here**: KNNImputer.fit_transform builds the neighbor graph on the full matrix including pseudo_1 (holdout) cells. Two holdout cells that are similar in all non-masked markers can be mutual neighbors, enabling better imputation than a train-only model allows. CytoVI is trained strictly inductively (never sees masked values). The B7 imputation comparison between CytoVI and KNN is therefore asymmetric — KNN has an inductive advantage.
**Fix**: Replace with `KNNImputer(...).fit(x[train_mask]).transform(x[holdout_mask])[:, midx]` to make KNN strictly inductive, matching CytoVI's evaluation mode.

##### F7. B4 control cell selection uses first N rows, not a random sample
`benchmarks/cytoanvi/tasks.py:2903` (diffed version) — also flagged by 3 other sub-agents

##### F8. Population std (ddof=0) underestimates variability at n=3 seeds
`benchmarks/common/seeds.py:911`
```python
out[k] = {"mean": float(arr.mean()), "std": float(arr.std(ddof=0)), "n": len(vals)}
```
**Why it matters here**: At n=3 seeds, ddof=0 produces a std 18.4% smaller than the unbiased sample std (ddof=1). All downstream delta std calculations in `aggregate_results.py` that use these values will understate the seed-to-seed variability, making confidence intervals appear tighter than they are.
**Fix**: Change `arr.std(ddof=0)` to `arr.std(ddof=1)` throughout `seeds.py`. Add `n` to outputs so SEM can be computed externally.

##### F9. B5 novelty detection is transductive — novel cell profiles present during training
`benchmarks/cytoanvi/tasks.py:279`
```python
masked[is_novel] = unlabeled_category   # only labels blanked
model, a = train_cytoanvi(work, ...)    # work contains novel cells' marker profiles
unc_latent = model.get_uncertainty(mode='latent')  # scored on training cells
```
**Why it matters here**: The task tests whether uncertainty scores are higher for cells whose labels were withheld, even though the model observed those cells' full marker profiles during training (in the unlabeled ELBO term). This measures uncertainty calibration for training-visible profiles, not true OOD detection. The distinction matters for how the paper frames the B5 claim. If the intent is calibration testing, this is by design; if the intent is OOD detection, the novel cells must be excluded from training.
**Fix**: If the claim is OOD detection, exclude `is_novel` cells from training and evaluate inductively. If the claim is calibration, add a sentence to the methods clarifying this.

##### F15. CD45RA/CD45RO max-collapse erases naive/memory T cell distinction
`src/scvi/external/cytovi/marker_harmonization.py:collapse_cd45_markers()`
```python
cd45 = out[cols].max(axis=1)   # max(CD45, CD45RA, CD45RO) per cell
```
**Why it matters here**: CD45RA (naive T cells) and CD45RO (memory T cells) are functionally exclusive isoforms. Both naive T (CD45RA_high) and memory T (CD45RO_high) produce CD45_high after max-collapse. For Roider BNHL and immune profiling, naive/memory T cell ratio is a primary biological variable. CytoANVI trained on collapsed markers will assign naive and memory T cells to the same latent region.
**Fix**: If the goal is RNA-CyTOF harmonization (only total PTPRC available in RNA), document explicitly that this collapse destroys naive/memory T resolution. Consider adding `collapse_method: Literal['max', 'sum', 'mean']` parameter. If downstream labels include Naive T and Memory T as separate categories, keep CD45RA and CD45RO separate.

##### F16. Fisher importances documented as "unsupervised ELBO only" but semi-supervised loss is used in practice
`src/scvi/external/cytoanvi/_continual.py:92`
```python
# Docstring: "Uses the **unsupervised ELBO** only (no labelled minibatch / classification term)"
# Code:
loss = model.module.loss(tensors, inf, gen).loss  # semi-supervised loss; labeled cells get classifier term
```
**Why it matters here**: EWC protects parameters proportionally to their Fisher importance. If the classification term is underweighted (by using mostly unlabeled cells in the replay buffer), the encoder_z2_z1 and classifier weights get low importances and can drift freely during Phase-2 — defeating the purpose of EWC for preserving cell-type classification.
**Fix**: Either (a) explicitly add the classification term for labeled cells and update the docstring to reflect this, or (b) update the docstring to say the semi-supervised loss IS used and verify classifier param importances are non-zero empirically.

##### F17. `except Exception` in B1 harmony baseline swallows all errors — crashes appear as missing data
`benchmarks/cytoanvi/tasks.py:~2587`
```python
try:
    hm_pred_unlab, _, hm_unlab_mask = harmony_latent_and_knn(...)

```
**Why it matters here**: Any code bug inside `harmony_latent_and_knn` (wrong obs key, shape mismatch, import of missing package) is silently stored as `{"error": "..."}` and then silently dropped from the B1 aggregated summary (because `_get(payload, "harmony_knn", "macro_f1")` returns None for an error dict). **Fix**: Replace `except Exception` with the two expected failure modes: `except ImportError` (harmonypy not installed) and `except (ValueError, KeyError)` (configuration error). ##### F20. `mask_augment` uses global torch RNG — TTA uncertainty scores not reproducible across calls
`src/scvi/external/cytoanvi/_uncertainty.py:~1984`
```python

```
**Why it matters here**: `get_uncertainty()` with TTA is not reproducible across calls unless `scvi.settings.seed` was set before each call. ##### F21. PCA in harmony baseline uses hardcoded `random_state=0` instead of benchmark seed

```python
def _run_tasks(args, p1, p2, unlab, seed):
    scvi.settings.seed = seed   # global mutation inside per-seed function
```
**Why it matters here**: When `run_multiseed` calls this function multiple times in the same process, each seed call reseeds PyTorch/NumPy globally. The random state entering seed N+1 depends on exactly how many random calls happened during seed N, making multiseed aggregation non-reproducible in theory (though in practice each seed's isolation may be sufficient if the calls are sequential).
**Fix**: Set `scvi.settings.seed` once before the multiseed loop; derive per-run state explicitly from `seed` at each function entry using a local `rng = np.random.default_rng(seed)`.

##### F29. `np.random.choice` unseeded in test fixture factory — test results depend on global RNG state
`tests/external/cytoanvi/test_cytoanvi.py:~32`, `test_hce.py:~106`, `test_hierarchy.py:~389`
```python
def _make_adata(n_genes=30, ...):
    adata.obs[SAMPLE_KEY] = np.random.choice(['group_a', 'group_b'], size=adata.shape[0])
```
**Why it matters here**: The same test produces different data when run in isolation vs. a full test suite, or when test order changes. This can cause flaky failures on edge-case splits (e.g., an empty group).
**Fix**: Replace with `rng = np.random.default_rng(42); adata.obs[SAMPLE_KEY] = rng.choice(...)`.

##### F30. `MockTreeNode` class duplicated with subtle variations across two test files
`tests/external/cytoanvi/test_hierarchy.py:~294` and `tests/external/cytoanvi/test_hierarchy_schpl_mock.py:~458`
**Why it matters here**: The two implementations differ (one accepts `ancestor` in `__init__`, one doesn't; one uses underscore prefix). When the hierarchy module's expected interface changes, both test mocks must be updated independently.
**Fix**: Extract into `tests/external/cytoanvi/_helpers.py` (or `conftest.py`) and import in both test files.
